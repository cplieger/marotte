              Pull request checks

              Workflow runs

              When a workflow run finishes, fails or is stopped, whether you, the agent or a schedule started it.

              Kiro sign-in

              When marotte cannot renew your Kiro sign-in for 2 minutes, or the sign-in ends. Once per problem, until it works again.

              Permission needed

              Always on, because the agent waits until you answer an approval. To be asked less often, choose a looser profile in Permissions.

              Display

              How times of day are shown, on this device only. Automatic follows your browser's language and time format.

              Composer

              What the first half of the send button does with a message you send while the agent works, in every chat, and what Enter does where Enter sends. Steer lets the agent read it mid-turn. Queue holds it until the turn ends, and queued messages go one per turn. When both halves show, the second does the other. Steer is the default.

              Chat retention

              Closed chats stay in History for the Days kept, or for good with Keep forever. With Days kept above 0, finished workflow runs are deleted that many days after they last ran, even while their chat stays open. Set 0 to delete a chat as soon as you close it.

              Keep forever

              How long a chat you close stays in the sidebar's History, up to the 10 most recent. 24 hours is the default, and the History page keeps a closed chat for as long as Chat retention does.

              Links

              Guard links with encoded payloads

              A link in the agent's replies whose address carries a lot of encoded data, a common way to leak information, becomes a button that copies the link instead of opening it. On by default, and unsafe links stay blocked either way.

              Agent capabilities

              What the agent can use. Changes reach new chats, and open chats at their next message, except a row that says it applies after the agent engine restarts.

              Knowledge base search

              Lets the agent search the folders you have indexed in Custom instructions. On by default, and turning it off keeps the indexes.

              Best finds passages by meaning; Fast matches words only and indexes faster. Default follows Kiro, which uses Best, and a knowledge base keeps the type it was added with.

              Indexes only the files whose path in the folder matches one of these patterns, separated by commas. Empty, the default, indexes every file Kiro can read, and a knowledge base keeps the patterns it was added with.

              Leaves out the files whose path in the folder matches one of these patterns, separated by commas. Hidden folders and folders such as node_modules and build are always left out, and a knowledge base keeps the patterns it was added with.

              The most files Kiro indexes from one folder when you add or reindex a knowledge base; it skips the rest. 10000 by default; raise it for a larger folder.

              When you add or reindex a knowledge base, Kiro splits each file into passages of this many words, each starting with the last Overlap words of the one before. 512 and 128 by default; smaller passages make each search result shorter.

              Code intelligence

              Checking the installed language servers. A language server gives the agent navigation, rename and error checking for its language, in open chats too.

              Model fallback

              When a model declines a request or is unavailable, Kiro retries the turn on another model from its fallback chain, and the chat may move to that model unless you picked one. On by default, as in Kiro.

              Belongs to the Kiro account signed in on this machine, shared with kiro-cli. Applies to new chats.

              Ask clarifying questions first

              Steering reminders

              Background jobs

              Long commands move to the background and the chat is woken when they end. While on, commands run inside kiro-cli, not marotte's terminal: they get kiro-cli's screened environment and the process tools go away.

              Open chats switch at their next message.

              Gives the agent a reviewer it can call to challenge a large change before calling it done. Default follows Kiro; choose On to have larger changes checked.

              In a chat on Auto, Kiro may move to a stronger model partway through when a task needs it, and the chat notes where it did. Default follows Kiro; choose Off to keep a chat on the model it started with. Choosing On or Off also replaces Kiro's server-tuned context hand-off wording with its built-in one.

              In a chat on Auto, Kiro may run a helper agent or workflow step on a cheaper or stronger Auto model to suit its task. Default follows Kiro; choose Off to stop it.

              When the agent edits a CloudFormation template or runs a CDK deploy or destroy, Kiro checks the change against your account's safety rules. Warn tells you when it breaks one; Block until you allow also stops the change until you choose, and a scheduled or triggered run keeps it blocked. Default follows Kiro. The check sends the template and recent chat to Kiro's service.

              Workflows

              On: the agent can start workflows that run in the background while you keep chatting, and Workflow use says when. Off: it uses subagents instead and waits for each to finish before it continues. Runs you start from Docs > Workflows work either way. On by default.

              When the agent starts a workflow on its own. Only when asked: it does the work in the chat unless you ask for a workflow. Only for large tasks: it starts one for multi-step work or work that would fill the chat's context. As much as possible: it hands reading code, writing it, testing and review to workflows. Chats started on an older kiro-cli keep handing all work to workflows. Only when asked by default.

              How much reasoning Kiro spends planning a workflow the agent starts from a description rather than a saved workflow. Default lets Kiro decide; raise it if those workflows miss steps.

              How many runs that forge events started may run at the same time, across every workflow, from 1 to 100. An event past the limit waits until one ends. 3 by default.

              How many runs forge events may start in any hour, across every workflow, from 1 to 100. An event past the limit waits for the hour to make room. 6 by default.

              Messages between chats

              On: the agent in one chat can message another chat, for example to say an API changed, and that chat's agent replies; sending needs Workflows on and a mode other than Plan, Autonomous, Spec, Quick Spec or Bug Fix. Turn it on when your chats work on related tasks; off by default.

              How many messages two chats' agents can pass back and forth in one exchange before Kiro stops delivering them, from 1 to 500. It keeps two agents from replying to each other forever. 50 by default.

              Search other chats

              On: the agent can use your other chats to build on earlier work or find a chat to message, and Search method says how. Off by default.

              How the agent reads your other chats. Browse and read: it lists and searches them and reads each one's summary itself. Ask a question: it asks once and a hidden helper reads the chats and answers, citing the chats it used, which keeps their text out of this chat but spends extra model calls. Default lets Kiro decide (Browse and read today). Applies to chats you start after the change.

              Default uses Kiro's standard response style.

              How many seconds a shell command may run when the agent sets no limit of its own: empty means 2 minutes, at most 30 minutes. Raise it if your builds or tests often take longer than 2 minutes.

              Agent engine

              One kiro-cli agent engine runs every chat and workflow. It restarts by itself when a setting below needs it and nothing is running.

              Restart the agent engine

              Applies any pending setting at once, or recovers an engine that stopped answering. Running replies stop, and running workflows pause and resume by themselves. Restarting also stops a signed-out account at once.

              The most memory, in MiB, the agent engine's JavaScript heap may use, from 1024 to 65536 and at most the container's memory limit minus 512. Empty keeps kiro-cli's default, about 4 GB. It bounds the JavaScript heap only, not the engine's native memory.

              Data sharing

              What Marotte and kiro-cli share with AWS. Both are on by default, as in kiro-cli.

              Share content with AWS for service improvement

              Lets AWS use what Marotte sends the model to improve its service: your chats and workflow runs. On by default, as in kiro-cli. It covers what Marotte sends; kiro-cli run in the Shell panel follows its own setting. A change applies at the next model request.

              kiro-cli telemetry

              Covers both kinds of kiro-cli telemetry: its usage telemetry, which sends usage data from kiro-cli and the chats it runs to the Kiro team, linked to your signed-in account, and its legacy toolkit telemetry. On by default, as in kiro-cli.

              Experimental features

              Optional kiro-cli features.

              Show hook status in chat

              Shows a card in the chat each time a hook runs. Hooks run either way.

              Exclude default resources from custom agents

              When on, custom agents in kiro-cli's v2 engine stop loading the default steering docs, skills and AGENTS.md, and start with only what their own definition includes. The v2 engine runs kiro-cli chat --v2 and non-interactive runs, which still default to it. kiro-cli's default terminal chat and Marotte chats do not read this setting.

              Debug logs

              Writes more detailed logs for troubleshooting. marotte's own log, read with docker logs marotte, switches at once. The agent engine's log under /config/home/.kiro/logs switches when the engine restarts.

              High throughput optimizations

              Starts the agent engine with Node.js memory and async-context settings that let it carry many chats and workflow steps at once. Turn it off for kiro-cli's stock engine.

              Wait for MCP servers before a prompt

              When on, a message waits until your MCP servers have connected, so their tools work from the first message. Off by default. Each server gets its connect timeout, 60 seconds unless its config sets another, up to 10 minutes. A server still connecting after that makes the message fail and names the server. A Power's server is the exception, and the message goes on without its tools and shows a warning.

Defaults here apply to new conversations, and the pills and the chat-options menu next to the prompt change the conversation you are in.

              Unattended runs

              Scheduled and triggered workflows run with nobody watching, so by default a request that needs approval is refused after 3 minutes and the run stops instead of waiting forever. Turn this on to approve those requests automatically, one at a time and never saved as rules. A triggered run can read text other people wrote, such as an issue body, and with this on a request that text leads it to make is approved too. A request your organization requires a person to approve, or that Kiro's safety check handed to a person, is still refused.
